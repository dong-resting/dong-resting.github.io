先建立一条线

初学网络最容易卡在概念彼此孤立：VLAN 是 VLAN，路由是路由，ARP 是 ARP。更好的方式是把它们挂到同一个过程上——一个包从进入接口到离开设备。

包到达接口

  1. 物理层收比特，成帧；
  2. 二层看目的 MAC：是自己的、广播、还是需要泛洪；
  3. 如果是三层接口，进入路由查找。

交换机的三张表

表作用关键点
MAC 地址表端口 ↔ MAC学习源 MAC，查目的 MAC
ARP 表IP ↔ MAC三层转发前必须解析
路由表目的网段 → 下一跳最长匹配优先

交换机转发看 MAC 表，路由器转发看路由表。这句话听起来简单，但配置时把两者搞混是大部分实验失败的起点。

最长匹配

路由查找不是「先配先生效」，而是掩码最长优先：

10.1.0.0/16  -> 下一跳 A
10.1.1.0/24  -> 下一跳 B

访问 10.1.1.5 会命中 B，因为 /24 比 /16 更具体。只有掩码长度相同时，才比较管理距离（AD）和度量值。

默认路由的位置

0.0.0.0/0 是掩码最短的路由，永远最后被匹配。它不应该用来「兜底解决」实验中的连通性问题——能通，但你可能并不知道包走了哪条路。排查时用 tracert 或 display ip routing-table 确认实际路径。
