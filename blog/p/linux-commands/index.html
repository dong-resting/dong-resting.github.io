顺序比命令重要

线上出问题时最怕东敲一条西敲一条。固定顺序能少走弯路：资源 → 进程 → 网络 → 日志。

资源

uptime                 # 负载与运行时间
free -h                # 内存，注意 available 而不是 free
df -h                  # 磁盘
df -i                  # inode，小文件写满时磁盘看起来还有空间
top -o %MEM            # 按内存排序

进程

ps aux --sort=-%cpu | head
pgrep -af nginx
lsof -p <pid> | wc -l  # 句柄数，文件描述符泄漏常在这里
strace -p <pid> -f -e trace=network

网络

ss -lntp               # 监听端口，比 netstat 快
ss -s                  # 连接状态汇总
ip -br a               # 网卡与地址
ip route get 8.8.8.8   # 实际走哪条路由
tcpdump -i any -nn port 80 -c 20

日志

journalctl -u nginx --since "10 min ago" -p err
journalctl -k -p err            # 内核
tail -f /var/log/nginx/error.log

几个容易忽略的点

  • df -h 正常但写不进去，先查 inode；
  • 内存告急先看 available，free 数值低是正常的缓存占用；
  • 连接数异常先区分 TIME_WAIT 和 CLOSE_WAIT，后者几乎总是应用没关连接。
