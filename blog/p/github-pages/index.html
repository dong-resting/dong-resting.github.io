把博客放到 GitHub Pages 的三个坑

自定义域名、路径大小写、缓存——上线后页面白屏，多半是这三件事之一。

坑一：自定义域名只配了一半

在仓库设置里填了域名，DNS 也加了 CNAME，但打开仍是 404。原因通常是：

  • 仓库根目录缺少 CNAME 文件（只填设置页不够，部署时会覆盖）；
  • DNS 的 CNAME 指向了 username.github.io 而不是仓库名；
  • 开了 HTTPS 但证书还在签发中，这时 http 能通、https 不通。

坑二：Linux 认大小写，Windows 不认

本地 Style.css、引用写 style.css，在 Windows 上完全正常，推上去就是 404。上线前统一检查一遍引用路径，或者干脆全部用小写命名。

排查方法：浏览器控制台看 404 的具体 URL，和仓库里的文件名逐字比对。

坑三：缓存让你以为没生效

改了 CSS 刷新没变化，大概率是缓存。分层排查：

  1. 无痕窗口；
  2. 强制刷新（Ctrl + F5）；
  3. 查看响应头的 cache-control 与 etag；
  4. 确认 Actions / Pages 的部署真的跑完了，而不是排队中。

一个习惯

每次部署后在手机上打开一次。移动网络和 WebView 的缓存策略跟桌面浏览器不一样，很多问题只在那里出现。
